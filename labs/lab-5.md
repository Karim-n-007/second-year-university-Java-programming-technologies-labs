# Лабораторная работа №5

## Отрабатываемый материал
- Message brokers (Apache Kafka / RabbitMQ)
- Публикация и потребление потока событий между Spring Boot-приложениями

## Задание

Необходимо доработать существующую банковскую систему (реализованную в лабораторных работах №2-4), реализовав новое Spring Boot-приложение и доработав старое, организовав взаимодействие между двумя сервисами через брокер сообщений.

Существующий функционал, реализованные ранее, остаются без изменений - добавляется только межсервисное взаимодействие и пересчёт балансов в валюту.

## Архитектура

Система состоит из двух сервисов:

### `bank-service` (основной сервис из ЛР 2-4)
Банковское приложение. Все счета ведутся в рублях, как и раньше. Сервис слушает поток котировок из брокера и умеет по запросу клиента показывать баланс счёта в выбранной валюте.

### `rates-service` (новый сервис)
Отдельное Spring Boot-приложение - поставщик котировок валют. Периодически генерирует новые курсы (USD, EUR и т.п. к рублю) и публикует их в брокер. Также умеет отвечать на точечные запросы о курсе конкретной валюты.

## Предметная область

Все счета пользователей по-прежнему хранятся и изменяются в рублях - операции пополнения, снятия и перевода работают так же, как в предыдущих лабораторных.

Добавляется возможность получать баланс и историю операций счёта в выбранной валюте (USD, EUR и др.). Конвертация выполняется по курсу, пришедшему из `rates-service`.

### 1. Поток котировок (fire-and-forget)

`rates-service` раз в какое-то время публикует в брокер сообщения вида:

```json
{ "currency": "USD", "rateToRub": 67.67, "timestamp": "..." }
```
```json
{ "currency": "EUR", "rateToRub": 14.88, "timestamp": "..." }
```

`bank-service` слушает этот топик / очередь и держит у себя в памяти актуальные курсы. При запросе баланса в валюте использует последний полученный курс.

Курсы должны реально меняться (например, случайно колебаться в заданном диапазоне), чтобы на сдаче это было видно.

### 2. Точечный запрос курса (request-reply)

В `bank-service` добавляется эндпоинт, позволяющий Client'у получить баланс своего счёта в указанной валюте (например, `GET /accounts/{id}/balance?currency=USD`).

Если в базе `bank-service` по этой валюте нет актуального курса (например, курс слишком старый или данных вообще нет), то `bank-service` отправляет запрос на курс (через эндпоинт) и получает ответа от `rates-service`.

Если курса нет в `rates-service` - эндпоинт возвращает осмысленную ошибку.

## Функциональные требования

1. `rates-service` публикует в брокер обновления курсов валют с настраиваемой периодичностью.
2. `bank-service` подписан на топик / очередь с курсами и поддерживает локально актуальные значения.
3. В `bank-service` добавляется возможность запрашивать баланс счёта в выбранной валюте (как минимум USD).
4. Если актуального курса в кэше нет - `bank-service` запрашивает его у `rates-service` через ручку.
5. Все внутренние операции (пополнение, снятие, перевод, расчёт комиссий) по-прежнему выполняются в рублях - конвертация применяется только на чтение.
6. Если `rates-service` недоступен и нужного курса нет в базе - клиенту возвращается осмысленная ошибка, остальной функционал банка продолжает работать.

## Нефункциональные требования

- Разрешается использовать **Apache Kafka** (c `KafkaTemplate` и `ReplyingKafkaTemplate` + `@KafkaListener` с reply-топиком) либо **RabbitMQ** (c `RabbitTemplate.sendAndReceive` + `@RabbitListener`). Использование JMS-брокеров (ActiveMQ и т.п.) запрещено.
- Схема request-reply для точечного запроса курса должна быть реализована именно через брокер, а не через прямой HTTP-вызов.
- Поток котировок должен идти через брокер как обычные события (fire-and-forget), без ответов.
- Периодичность публикации курсов и таймаут request-reply должны настраиваться.

Обратите внимание, что currency код всегда трёхзначый
